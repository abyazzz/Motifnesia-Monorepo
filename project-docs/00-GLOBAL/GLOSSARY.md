# Glosarium

| Istilah | Arti |
| --- | --- |
| AS-IS | Kondisi operasional toko yang ditemukan dalam bukti penelitian. |
| AS-IMPLEMENTED / CURRENT | Keadaan kode dan skema yang dapat dibuktikan pada audit monorepo. |
| TO-BE / TARGET | Proses dan kebutuhan yang telah ditetapkan pada artefak target. |
| PROPOSED | Rancangan teknis untuk memenuhi target dan masih memerlukan review. |
| TBD | Detail, keputusan, atau bukti yang belum tersedia atau belum disepakati. |
| KF | Kebutuhan fungsional. Sumber aktif memuat KF-01–KF-18. |
| UC | Use Case. Daftar dan skenario final memuat UC-01–UC-64. |
| RB | Aturan bisnis lintas proses dalam TO-BE. |
| Gate / ability | Pemeriksaan izin Laravel dan representasi kemampuan pengguna untuk client. |
| PO | Purchase Order. Pencetakan dan pengunduhan dokumen ini termasuk UC-30. |
| Reservasi stok | Pengikatan jumlah barang per varian dengan pesanan supaya persediaan tidak dijanjikan ganda. |
| Stock opname | Pencatatan hitung fisik, selisih dari stok sistem, dan penyesuaian yang tercatat. |
| Payment Gateway | Layanan eksternal pemroses pembayaran pada rancangan TO-BE. |
| Refund | Pengembalian dana manual oleh Finance di luar sistem serta pencatatan status dan bukti di MotifNesia dalam target. |
| Supplier | Pihak pemasok. Memiliki portal pada aplikasi saat ini dan berkomunikasi eksternal dalam target. |
| View envelope | Respons API v1 `page`, `data`, dan `viewer` yang dikonsumsi kedua client. |
